# Decisions

One line per decision, with the date and the reason. Newest at the bottom. Longer context lives in `docs/wiki/`.

- 2026-11-21: App renamed Replyly (repo `paragrudani1/replyly`, package `com.paragrudani.replyly`). Reason: Parag's request.
- 2026-11-21: One branch and one PR per ticket against `main`, after a skeleton/shared-contracts PR. Reason: parallel tickets need stable interfaces to avoid conflicts.
- 2026-11-21: Chief of staff reviews and merges PRs once CI is green; Parag does not review. Reason: Parag handed end-to-end ownership to CoS plus the product-owner Claude.
- 2026-11-21: Anything that needs a physical S23 goes into `docs/DEVICE_CHECKLIST.md` with exact steps. Reason: no silent guesses about WhatsApp view IDs, overlay placement or One UI behaviour.
- 2026-11-21: A debug keystore is committed to the repo and used for every build. Reason: a stable signature lets Parag install an update over the old APK without losing the encrypted history.
- 2026-11-21: The APK is published as the rolling GitHub release `latest-debug` (asset `replyly-debug.apk`) on every push to main. Reason: one stable download link for sideloading.
- 2026-11-21: Manual DI (`AppGraph`), no Hilt. Reason: single-user app; fewer build dependencies; each ticket swaps one binding.
- 2026-11-21: Default model `anthropic/claude-haiku-5.5`; quick picks `google/gemini-3.8-flash` and `~openai/gpt-mini-latest` (all three listed on OpenRouter's /models that day). Reason: spec shortlist; no Lite/nano.
- 2026-11-21: PRs merge with merge commits, not squash. Reason: ticket branches stack on the skeleton until it lands; merge commits keep their ancestry intact.
- 2026-11-21: Ticket agents write S23-only checks to `docs/device-checklist/ticket-<N>.md`; CoS merges them into `docs/DEVICE_CHECKLIST.md`. Reason: avoid merge conflicts between parallel tickets.
- 2026-11-21: Toolchain JDK temurin-21 (mise.toml), AGP 9.5.2, Kotlin 2.4.21, Gradle 9.9.2, compile/target SDK 37, minSdk 34. Reason: latest stable that resolved on 2026-11-21 (skeleton agent).
- 2026-11-21: Two SQLCipher DBs (history owned by #3, feedback owned by #6) with one Keystore-protected key. Reason: keeps parallel tickets out of each other's Room schema.
- 2026-11-21 (#4): Parallel mode (3 calls, intents fixed agree/decline/ask) counts as 1 daily request, sums tokens, and fails as a whole if one call fails. Reason: one tap = one request; the contract needs exactly 3 suggestions.
- 2026-11-21 (#4): LLM error details use fixed wording per HTTP status and exception type only, never provider text or exception messages. Reason: those can echo the prompt.
- 2026-11-21 (#4): Requests send only model, messages, max_tokens (1024; 512 per parallel call) and response_format (retried without it once if rejected, remembered per model); no temperature. Reason: some reasoning models reject temperature.
- 2026-11-21 (#4): Prompt caps: 12k chars of history (oldest dropped), 600 per message, 25 style examples of 200 chars (last 20 from this chat, 15 from other chats, deduped), About me 1,500, note 1,000, instruction 300. Reason: bound cost and latency.
- 2026-11-21 (#6): Endpoint must be https. Reason: the API key never travels over plain HTTP.
- 2026-11-21 (#6): Settings bounds: N 1–200, retention 1–365 days, daily limit 1–5000, About me ≤1000 chars. Reason: catch typos.
- 2026-11-21 (#6): Blocklist edits save immediately (not on Save). Reason: blocking is a privacy action.
- 2026-11-21 (#6): An undecryptable API key (e.g. after reinstall) is deleted and reads as "no key". Reason: ask again instead of failing every request.
- 2026-11-21 (#6): Cost counters never roll backwards. Reason: a clock change must not grant a fresh daily allowance.
- 2026-11-21 (#4 review): With an openrouter.ai endpoint, requests send `reasoning: {effort: "low"}`; a reply cut off at the token limit (`finish_reason: length`) becomes a fixed "cut off" BadOutput. Reason: reasoning tokens count toward max_tokens and blow the 1–2 s target.
- 2026-11-21 (#4 review): Replies match the language, mix and script the user writes in this chat (fallback: the latest messages). Reason: a contact writing English or Devanagari should not pull the user's Hinglish replies away from their own style.
- 2026-11-21 (#4 review): The conversation goes into the prompt inside `<conversation>` tags marked untrusted; titles and sender names lose newlines. Reason: limit prompt injection from chat text.
- 2026-11-21 (#4 review): Style examples: at most 10 from this chat, so other chats of the app get 10–15. Reason: spec section 6.
- 2026-11-21 (#6 review): Save never writes blocklists; a stored cost day more than 1 day in the future snaps back to today keeping counts; a corrupt cost file resets to empty (fresh allowance). Reason: no silent unblocking; a wrong clock must not lock the app for months; corruption is rare and recoverable.
- 2026-11-21 (#6 review): A final sent message attaches only to an inserted feedback entry younger than 6 hours. Reason: keeps the feedback log's pairs meaningful.
- 2026-11-21 (#4 fixes): New `Failure.InvalidApiKey` (key with non-visible-ASCII chars), separate from `NoApiKey`. Reason: the error card can tell the user to paste the key again. #5 must handle it.
- 2026-11-21 (#3): History merge lines up a screen read against the saved tail like a diff; a missing time or a missing sender on someone else's message still matches. Reason: the top bubble's time gets clipped and group name labels scroll away.
- 2026-11-21 (#3): A read overlaps history only if at least half of its messages within the saved range match; otherwise it is appended. Reason: bubbles show time without date, so yesterday's "gm 9:00 am" must not match today's.
- 2026-11-21 (#3): Edits are recognised only with the same author and time shown; messages no longer on screen stay saved (no deletion detection); reads with no overlap append at the end even if older. Reason: false edits or deletes lose data; the screen gives no absolute dates.
- 2026-11-21 (#3): One passphrase (Keystore-wrapped, no-backup file) for every DB. A lost or invalid key wipes all DBs and makes a new one; an unopenable history.db is recreated; temporary Keystore errors throw `DatabaseKeyUnavailableException` and wipe nothing. Reason: losing history beats a service that crash-loops.
- 2026-11-21 (#3): Feedback final message is attached once per capture, from my newest message below the saved tail, only when the read overlapped. Reason: avoid tagging old messages as the sent reply.
- 2026-11-21 (#6 fixes): `CostGuard.refresh()` (default no-op) recomputes usage on screen resume; save errors show as a one-shot snackbar. Reason: deep sleep pauses timers; blocklist edits happen without the Save bar.
- 2026-11-21 (#7): "Restricted settings" counts as done once the accessibility service is enabled; the accessibility step needs enabled AND connected; "Sleeping apps" is a persisted manual confirmation. Reason: no API reads restricted settings or Samsung's sleeping list; an enabled-but-killed service does nothing.
- 2026-11-21 (#7): App opens on onboarding until all steps are done, then Settings; "Skip for now" is allowed. Reason: step 5 is done in Settings; personal app.
- 2026-11-21 (#1 brief): Inserting a suggestion replaces the input field's current content, cursor at end. Reason: ACTION_SET_TEXT sets the whole field; the user edits afterwards.
- 2026-11-21 (#3 review): Merge anchors on ≥2 exact matches (1 only for "new below"), edits only between aligned pairs with equal times (and senders), ties broken by fewest mismatches then newest. Reason: the review showed single or wildcard matches overwrote saved messages.
- 2026-11-21 (#3 review): DBs are wiped only on `SQLiteDatabaseCorruptException`, and keys count as lost only when the alias is gone or permanently invalidated; other errors are transient. Reason: a full disk or a boot-time Keystore hiccup must not delete history.
- 2026-11-21 (#3 review): Passive capture waits 1 s after the last change but at most 3 s total. Reason: typing indicators and GIFs change content continuously.
- 2026-11-21 (#3 review): Known limit: retention counts from when Replyly first saw a message, and purges can leave gaps mid-chat. Reason: bubbles have no absolute dates; accepted for a personal app.
- 2026-11-21 (#2): Bubble side is decided by shared left/right edges first, then read ticks, then the nearer edge. Reason: in groups the avatar column pushes wide incoming bubbles right, so "right = me" alone flips them.
- 2026-11-21 (#2): In a group, a sender name carries down to following bubbles until one of mine; a bubble before any name label gets sender null. Reason: no guessing; #3 fills it in later from an aligned read.
- 2026-11-21 (#2): Telegram parses each message cell's accessibility text ("Sent/Received … time"); geometry is the fallback. Reason: Telegram draws custom cells without view ids.
- 2026-11-21 (#2): Debug dumps are stored unencrypted in app-private, non-backed-up storage, only on a user tap; screens blocked by the sensitive policy are never dumped. Scramble keeps digits and times. Reason: dumps must stay parseable to become fixtures; digits were requested.
- 2026-11-21 (#5): Panel input caps match the prompt caps (instruction 300, note 1,000); Regenerate is ignored while a call runs; the keyboard's Done never calls the model. Reason: nothing cut silently; one tap = one paid request.
- 2026-11-21 (#5): Feedback-log failures never block suggestions or insert; assembler/generator/inserter exceptions show fixed wording. Reason: the log is only for later quality checks; no chat text in errors, no service crash.
- 2026-11-21 (#5): Delete-history confirmation lives inside the panel (no Dialog) and warns that on-screen messages are saved again; a note that failed to load never opens the editor. Reason: overlays have no Activity token; saving an empty editor would erase the note.
- 2026-11-21 (#5 review): One panel state per open, with its own Job cancelled when the panel goes away; HTTP 400/403/404/413 offer "Open settings", not Retry; insert failures show fixed text; `BadOutput.cutOff` flag replaces string matching. Reason: no LLM call without a tap, no paid retries that must fail, no node text in UI.
- 2026-11-21 (#7 review): Start destination is decided off the main thread (IO, 2 s cap, saved across rotation) before NavHost is built; system screens open without NEW_TASK; finishing onboarding pops back to an existing Settings. Reason: no ANR at launch, Back returns to Replyly, no duplicate Settings on the stack.
- 2026-11-21 (#2 review): With view ids, a sender label means incoming and a read tick means mine; geometry calls a bubble "right" only when its right gap is ≤ ~5% of the width. Reason: the group avatar column made wide incoming bubbles look like mine.
- 2026-11-21 (#2 review): Chat titles come only from the top band above the list, skipping pinned-message bars and unread badges; otherwise no chat. Reason: a wrong title merges unrelated histories and puts message text into DB keys.
- 2026-11-21 (#2 review): Scramble keeps only exact status strings (online, last seen…, N members, the encryption notice, typing…); sender names scramble consistently within a dump. Reason: prefix rules leaked whole messages; fixtures need the same-sender signal.
- 2026-11-21 (#2 review): The debug dump delay is 5/10/15 s (default 10). The fixture generator is committed at `scripts/fixturegen/gen.py`. Reason: switching apps closes the keyboard; fixtures must be regenerable.
- 2026-11-21 (#3 fixes): Editing the first or last visible message is stored as a new message, not an edit; a scroll-up showing only one saved message appends (one duplicate). Reason: at the edges, "same author, same minute, different text" is usually a new message, and treating it as an edit loses data.
- 2026-11-21 (#3 fixes): A key lost while the app runs is handled at the next start (no wipe under open DBs). A pair differing only by a missing sender (same text, equal shown times) may anchor the merge. Reason: group name labels scroll away; no duplicates for the common group case.
- 2026-11-21 (#1): FLAG_SECURE is probed with `takeScreenshotOfWindow` (buffer closed at once, nothing decoded), cached per window for 1 s; if the probe can't tell, it fails open and logs. Reason: accessibility can't read FLAG_SECURE; a One UI quirk must not disable the app, and the app/banking/password/chat rules still apply.
- 2026-11-21 (#1): Until settings load, every app counts as blocklisted; the tap reads the chat's window by id (not the active window); the button never shows over Replyly or System UI. Reason: never read a blocklisted chat at start-up; touching the overlay can change the active window.
- 2026-11-21 (#3 re-review): History has gap segments: the first row of an unanchored append gets `gapBefore`; merges never pair, edit or fill across a gap; trailing new messages go right after their anchor; `newAtEnd` only when the anchor is the last saved row. A seeded property test (fuzzer) guards the merge invariants in CI. Reason: the second review still found overwrites and old replies logged as "sent" after a gap plus scroll-up.
- 2026-11-21 (#1 review): FLAG_SECURE probe fails CLOSED (anything but a clear "not secure" blocks the read); supersedes the fail-open line above. Reason: a missing screenshot capability would otherwise switch the protection off silently and forever.
- 2026-11-21 (#1 review): The panel closes on screen-off and when its chat window disappears; the inserter never falls back to another window of the app. Reason: overlays draw over the lock screen, and a card must never land in a different chat.
- 2026-11-21 (#1 review): The panel is a full-screen modal with a dimmed backdrop and ADJUST_RESIZE (not #5's suggested touch-through/ADJUST_PAN). Reason: the chat must not change under an open panel; #5's KDoc is updated at integration.
- 2026-11-21 (#1 review): `InvariantsTest` also requires `performAction(` only in `insert/AccessibilityInputFieldSource.kt`. Reason: raw action ids bypassed the name-based check.
- 2026-11-21 (#2 fixes): Telegram group: a multi-line incoming cell's first line is the sender only if it repeats as a first line, matches a typing name, or looks like a name (≤4 words, ≤40 chars, capitalised, no end punctuation); otherwise text. Geometry bubble = widest container narrower than the row. Reason: follow-up cells may omit the name; inner text views sit inside bubble padding.
- 2026-11-21 (#3 round 3): Accepted the fixer's extra merge rules: a read lined up on both sides of a gap closes it; edge rows must not contradict; at most one unpaired read message between pairs; a single pair anchors only on a distinctive text (8+ chars) with every field equal; "exact" needs shown times on both sides; purges mark the holes they leave. Reason: each rule removed a failure class the committed fuzzer found (35,761 reads over 300 seeds, 5.4 s).
- 2026-11-21 (#3 round 3): Accepted known limits, documented in `HistoryMerge` KDoc: a read far above saved history lands at the end; runs of identical messages can lose one copy; same-content runs on another day can be confused; edits at the visible edges are stored as new. Reason: the screen shows no dates; these cases are rare and lose at most one duplicate-looking message.
- 2026-11-21 (#3 final review): History tracks a per-chat current position (where the latest read was placed); `lastMessages` and style examples read up to it, not the physical end. Reason: an old block appended at the end (after scrolling far up) would otherwise feed stale messages to the prompt.
- 2026-11-21 (#3 final review): Accepted limit: an ambiguous run of identical messages with one time-less row can report one old "ok" as the sent reply in the feedback log (~1 in 36k simulated reads). Reason: feedback log only; fixing it costs more than it is worth.
- 2026-11-21 (#3 final review): Acceptance bar for the merge: ≤1% of 2,000 fresh fuzzer seeds per config fail outside documented limits, and zero overwrites. Reason: stop open-ended rounds; the committed property test guards regressions.
